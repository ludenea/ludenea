# Control surface toy

Throwaway spike of the control surface research. It exposes one command, one query and one event subscription over the [reference workload](../reference-workload/README.md), drives them with a scripted agent that discovers the contract through introspection, serves them in process and over local sockets, and measures, instead of assuming, whether the agent's view of the world equals the sequential oracle's and the world's stepped directly with the same inputs, whether the input log the server writes replays to the same hashes, whether a session survives a disconnection with every event delivered once and a retried command applied once, whether one compatible schema change leaves an old agent working while a new agent uses it, what the surface costs in process, and what a step costs over a local socket.

## Layout

- `src/world.rs`: the world, a trimmed copy of the [runtime skeleton](../runtime-skeleton/README.md) spike's core (the reference workload on the dependency-counting tick graph, stepped by whole ticks) plus the input fixed point: every tick of a step carries an ordered record of kicks (a velocity impulse on an entity by handle), validated against the state at the tick boundary (an alive entity whose generation matches, otherwise a deterministic rejection naming why) and applied before the tick's first system in record order, as the specification's clamp would. A sequential oracle steps the reference crate's systems with the same records.
- `src/contract.rs`: the contract description and its encodings, the [schema spike](../workload-schema/README.md)'s module: types, structures with stable names, versions, fields and defaults, enumerations, components, globals, commands, queries and events, values encoded by type in a canonical byte order, the description itself in a fixed bootstrap format.
- `src/surface.rs`: the surface. The description of the toy's contract (the `kick` command, the `entity_state` query, the `tick_completed` and `command_applied` events, the structural operations of the three components); sessions of two profiles (stepped, where the client owns the step call and observes in the same round trip; paced, where a host steps and a client's commands apply at the next tick boundary) with a token, subscriptions, a cursor and the idempotency keys seen; commands as elements of the next tick's record, written to the input log as canonical bytes; events retained with a per-world sequence number; the replay of a log on a fresh world; and the message envelope, with name-tagged parameters decoded against the description and structured errors (a stable code, a message, a context) for an unknown command, an unknown field, a missing field, a wrong type, a wrong profile, a lost cursor.
- `src/transport.rs`: one endpoint trait, three endpoints: in process (the request bytes handed to the server under its lock), a loopback TCP socket, and a Unix domain socket where the platform has one, both with length-prefixed frames, one thread per connection on the server side.
- `src/agent.rs`: the scripted agent. It knows the envelope, the description's format and its script (the names it wants) and resolves every name against the description at session start; the typed client runs the same script in process without encoding, the message client encodes requests over an endpoint and reconnects. The script watches sixteen entities, queries their state, kicks them toward the center of the world from their centroid every ten ticks, steps in batches of ten with the query answered at the end, and counts the events it receives and their sequence.
- `src/main.rs`: the scenarios and the report.

## Hypotheses

With the reference workload, version 1, default size (10 000 entities, 1 000 ticks), wander system off, compiled by one pinned Rust toolchain at default target features:

1. The agent, reading the contract description at session start and nothing else, steps the workload by batches of ten through a stepped session, kicks the entities it observed, reads their state and receives the tick and command events, and the per-tick hashes the events announce equal the hashes of the sequential oracle stepped with the kicks the same script decides from its own observations, and of the world stepped directly with those records: through the typed in-process client, the in-process message endpoint, the loopback socket and the Unix domain socket, at 1 and 4 workers (and the machine's core count) on every cell.
2. The input log the server writes replays on a fresh world to the hashes of the run that produced it, for every path and for the paced session.
3. Over the loopback socket the agent drops its connection after a command whose acknowledgement it treats as lost, resumes its session by its token and cursor, retries the command with the same key and is answered as the first time, and the run's hashes still equal the oracle's: the retried command applied once, every event received once, in sequence. Under a paced session (the host steps every millisecond) the agent polls, kicks when the tick crosses a multiple of ten, drops its connection for 30 milliseconds while the host keeps stepping, resumes from its cursor, and receives every tick's event once with the hash the world computed.
4. A field added to the kick command with a default (`scale`, schema version 2) is a compatible change: the version 1 script against a version 2 server gives the version 1 oracle's hashes; the version 2 script, which sets the field, gives the scaled oracle's hashes in process and over the socket alike; the version 2 script against a version 1 server is refused with an error naming the field; an unknown command and an unknown field are rejected with structured errors that name them, and the session goes on.
5. The surface in process with one observing session (a query of sixteen entities and the events of ten ticks per step, the input log written) costs under 2 percent of the tick against the world stepped directly at 4 workers; the round trip of a one-tick step with a query over each local transport is measured per cell, together with an empty round trip.

## Method

Per worker count: the sequential oracle (the kicks decided from its own observations); the world stepped directly with the oracle's records in batches of ten; the agent's script through the typed client, the in-process message endpoint, the loopback socket (with the disconnection at tick 500) and the Unix domain socket; each path's input log replayed; then one-tick steps for 200 ticks and 2 000 empty polls on each transport for the round trips. Once, at the largest worker count up to 4: the paced session over the loopback socket; the compatible change (the old script against the new server, the new script against the new server in process and over the socket, the new script against the old server, the two probes). Every run reports the agent's run hash, whether it matches its oracle and the first divergent tick, wall time and ticks per second, the step calls and the microseconds per call, the events (count, contiguity, duplicates, the step hash against the events), the outcomes, the reconnection and the retried key, the bytes exchanged, the input log's bytes and commands, and the replay's result.

The self-checks (`cargo test -p control-surface-toy`) verify on the small size that the world without kicks reproduces the sequential reference and with kicks agrees with the oracle at 1, 2, 3 and 8 workers in batches of 1, 7 and 40 with the same outcomes, that stale handles are rejected deterministically and two kicks add in record order, that a stepped session kicks, queries and observes with contiguous events and a log that replays, that a known key is answered from the record and applied once, that unknown commands, fields and missing fields are structured errors and defaults fill, that the message surface round trips and names unknown fields, that a paced session resumes from its cursor and an old cursor is an error, that the TCP and Unix endpoints answer like the in-process one and survive a reconnection, that an oversized frame is refused, and that the whole report runs with every check true.

## Environment

Research CI, workflow `research-ci.yml`, five cells (see [`spikes/README.md`](../README.md)), run on demand with `-f spike=control-surface-toy`. Rust toolchain pinned in [`rust-toolchain.toml`](../rust-toolchain.toml), release profile, default target features of each target; plus a local run on an Apple M5 (10 cores, macOS 26) outside the matrix. The Unix domain socket runs on the Linux and macOS cells only (the standard library has no named pipes, so Windows measures the loopback socket alone). Timings from hosted runners compare per processor only.
