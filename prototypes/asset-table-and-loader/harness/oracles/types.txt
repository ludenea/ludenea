# Family types: the asset type an entry holds.
# Written by hand from the design text as amended, by a writer who has not
# read the build.
# The table's order is the order of the asset identifiers:
# A, D, F, K, P, Q, S, W. S and W are of the second asset type.
# The table is empty before the first block of each scenario.
# Record lines stand in the order applied: the commands first, in the order
# the scenario gives them, then the arrivals by asset identifier.
# A refusal line under a record line says that the command is a recorded
# refusal: it changes nothing.
# The rules under test. The first want of an asset writes the type it states
# into the asset's entry. A later want of a command that states another type
# is a recorded refusal. The manifest is the authority on a type: the loading
# capability fails an asset the manifest holds under another type than its
# entry, and on an entry failed for that reason a want that states another
# type replaces the entry's type and is the new load. A want the core adds
# for a dependency is never refused. It states a type where it is the
# dependency's first and, on an entry failed for the reason of another type,
# where it takes the type its parent's part lists, replaces the entry's type
# and is the new load.

scenario types/want-of-another-type

# The host's want is the first of A and writes its type. The tool's want
# states another type: a recorded refusal, and the entry holds one want.
tick 2
record want A parameters source:host optional
record want A second source:tool optional
refusal other-type
entry A parameters unavailable
want source:host optional

tick 3
record arrival A A.1
entry A parameters available A.1
want source:host optional
event arrived A A.1

# The same refusal on an available entry, for a want an entity would own and
# that would be required. Nothing changes and nothing gates.
tick 5
record want A second entity:E1 required
refusal other-type
entry A parameters available A.1
want source:host optional

scenario types/wrong-first-want

# The first want states a type the manifest does not hold A under. The core
# has no manifest: the entry takes the type the want states.
tick 2
record want A second source:host optional
entry A second unavailable
want source:host optional

# The want left the domain with the type its entry holds, and the loading
# capability fails the asset: the manifest holds it under another type.
# The tool's command stands before that arrival in the record. Until the
# failure has arrived a want of another type is refused, the right type
# included: the entry is still unanswered when the command is applied.
tick 3
record want A parameters source:tool optional
refusal other-type
record arrival A failed other-type
entry A second failed other-type
want source:host optional
event failed A other-type

# The maker makes its want again. The entry is failed for the reason of its
# type, and the want states another type: it replaces the entry's type and is
# the new load, so the entry returns to unavailable. The host's want stays.
# Reading taken: the want made under the former type is kept as it is, since
# nothing ends a want but a release or the despawn of its owner.
tick 5
record want A parameters source:tool optional
entry A parameters unavailable
want source:host optional
want source:tool optional

# The want left with the type the entry now holds, which is the manifest's.
tick 6
record arrival A A.1
entry A parameters available A.1
want source:host optional
want source:tool optional
event arrived A A.1
