# Oracles of the family "order": the order at a tick's input fixed point.
# Written by hand from the design text as amended after the first stage,
# before any run of the same-harness stage, by a writer who has not read the
# build. Every state is derived again from the text, and none is patched.
# Every asset of this family is of the first asset type, written "parameters".
# An entry line states the type the entry holds, which its first want wrote;
# a want element of a record states the type its command carries.
# Record lines stand in the order applied: the commands first, in the order
# the scenario gives them, then the arrivals by asset identifier (A, B, G).
# A fall is derived from the table and is no element of a record.
# An entry line with no want line under it is an entry that holds no want.
# A tick block with no entry line states an empty table.
# Reading taken throughout: the events of a tick stand in the order in which
# its arrivals are applied, the order of the asset identifiers.

scenario order/want-and-arrival
# The want is applied before the arrival of the same record. It is the first
# want of A: it makes the entry and writes its type. The arrival then answers
# it: A is available from tick 4, under its want, with one event.
tick 4
record want A parameters source:host required
record arrival A A.1
entry A parameters available A.1
want source:host required
event arrived A A.1

scenario order/release-and-arrival
tick 2
record want A parameters source:host required
record arrival A A.1
entry A parameters available A.1
want source:host required
event arrived A A.1
# The release is applied first: the arrival at A.2 finds no want of A, changes
# nothing and emits no event. A keeps its entry through tick 5, with its type
# and its hash and with no want.
tick 5
record release A source:host
record arrival A A.2
entry A parameters available A.1
# A falls at the input fixed point of tick 6 and leaves: the table is empty.
tick 6

scenario order/want-again-after-release
tick 2
record want A parameters source:host required
record arrival A A.1
entry A parameters available A.1
want source:host required
event arrived A A.1
# The last want of A ends during tick 5: A keeps its entry, with no want.
tick 5
record release A source:host
entry A parameters available A.1
# The record of tick 6 is applied before the falls: A has a want again, does
# not fall, and stays at its hash without a gap. The want states the type the
# entry already holds. No event.
tick 6
record want A parameters source:host required
entry A parameters available A.1
want source:host required

scenario order/want-again-after-despawn
tick 2
record want A parameters entity:E1 required
record arrival A A.1
entry A parameters available A.1
want entity:E1 required
event arrived A A.1
# The despawn ends the want of E1 where it stands in the record of tick 5:
# A keeps its entry, with no want.
tick 5
record despawn E1
entry A parameters available A.1
# Wanted again at the tick of its fall, by another maker and as optional:
# A stays at its hash without a gap. No event.
tick 6
record want A parameters source:host optional
entry A parameters available A.1
want source:host optional

scenario order/want-again-live
# A live loading capability. The want of tick 2 names an unanswered asset: it
# leaves the world at the end of tick 2, its answer stands in the record of
# tick 3, and tick 2 runs with A unanswered.
tick 2
record want A parameters source:host required
entry A parameters unavailable
want source:host required
tick 3
record arrival A A.1
entry A parameters available A.1
want source:host required
event arrived A A.1
tick 5
record release A source:host
entry A parameters available A.1
# The want of tick 6 is applied on an entry the table holds available: it
# leaves nothing, no arrival answers it, and the input record gains nothing
# by it. The first stage's oracle had an arrival of A at the hash in force in
# the record of tick 7, under the reading that every want is answered.
tick 6
record want A parameters source:host required
entry A parameters available A.1
want source:host required
# The records of ticks 7, 8, 9 and 10 are empty, so those ticks have no block.

scenario order/accumulated-want-and-arrival
tick 3
record want G parameters source:host required
entry G parameters unavailable
want source:host required
# Gated on G from the boundary after tick 3. The gate leaves out the pending
# want of A, so the pending arrival of A answers nothing the table names, and
# G is unanswered: the step that does not wait names G alone.
blocked 4 awaiting G
# The arrival of G joins and opens the gate. The whole record is applied in
# order: the want of A, then the arrivals of A and of G, each answering a want.
tick 4
record want A parameters source:host required
record arrival A A.1
record arrival G G.1
entry A parameters available A.1
want source:host required
entry G parameters available G.1
want source:host required
event arrived A A.1
event arrived G G.1

scenario order/accumulated-release-and-arrival
tick 2

record arrival A A.1

want source:host required
event arrived A A.1
tick 3

want source:host required

tick 4

scenario order/gate-release-and-arrival
tick 3
record want G parameters source:host required
entry G parameters unavailable
want source:host required
# The step without waiting comes before anything is pending.
blocked 4 awaiting G
# The pending release of the required want counts as the answer of G, so the
# gate opens. The release is applied first: the arrival finds no want of G,
# changes nothing and emits no event. G never becomes available.
# An entry whose last want ended keeps its place for one tick boundary as it
# stood, one that never rose included: G stands here as unavailable, with its
# type and with no want.
tick 4
record release G source:host
record arrival G G.1
entry G parameters unavailable
# G leaves the table at the input fixed point of tick 5: the table is empty.
tick 5

scenario order/gate-arrival-and-new-want
tick 3
record want G parameters source:host required
entry G parameters unavailable
want source:host required
blocked 4 awaiting G
# The pending arrival answers G and the gate leaves out the pending want of
# B, so the gate opens. The want is applied before the arrival; tick 4 runs
# with B unanswered.
tick 4
record want B parameters source:host required
record arrival G G.1
entry B parameters unavailable
want source:host required
entry G parameters available G.1
want source:host required
event arrived G G.1
# The want of B gates from the boundary after its tick.
blocked 5 awaiting B
tick 5
record arrival B B.1
entry B parameters available B.1
want source:host required
entry G parameters available G.1
want source:host required
event arrived B B.1

scenario order/gate-pending-despawn
tick 3
record want G parameters entity:E1 required
entry G parameters unavailable
want entity:E1 required
# The first step without waiting, before anything is pending.
blocked 4 awaiting G
# The second step without waiting: the gate does not see the pending despawn
# of the owner, and stays closed on G.
blocked 4 awaiting G
# The arrival of G joins and opens the gate. The despawn ends the want of E1
# where it stands in the record, before the arrival: the arrival finds no want
# of G, changes nothing and emits no event. G never becomes available, and
# keeps its entry for one tick boundary, unavailable and with no want.
tick 4
record despawn E1
record arrival G G.1
entry G parameters unavailable
# G leaves the table at the input fixed point of tick 5: the table is empty.
tick 5
