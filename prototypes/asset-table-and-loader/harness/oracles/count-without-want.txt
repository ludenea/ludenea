# Oracles of the family "count-without-want": the count of a world keeps an
# entry in force that holds no want, though the record holds its arrival to
# failed.
# Written by hand from the design text as it reads after its second reading,
# by a writer who has not read the build.
# Asset identifiers order as B, D, N, P.
# Record lines stand in the order applied: the commands first, in the order
# the scenario gives them, then the arrivals by asset identifier.
# An entry line with no want line under it is an entry that holds no want.
# A tick 0 block states the table the creation gives.
#
# The availability source is scripted. Every arrival to a hash names the
# size of what it puts in force, and every available entry holds that size.
# A failed arrival and a failed entry hold none. Sizes in bytes: B.1 2 000,
# D.1 4 000, N.1 5 000, P.1 2 500. P.1 lists D.
#
# At an input fixed point, in this order: the commands of the record; the
# count; the groups, those of the roots that hold a required want first,
# each set in identifier order, each decided before any want is added from
# a part and before any arrival is applied; the wants that the parts of the
# accepted arrivals list, starting from an asset that holds a want; the
# arrivals in identifier order, a rejected one that fails its asset doing so
# at its own place; the wants the core added, recomputed from the parts in
# force; the falls.
#
# The sentence under test. The count of a world is the sum of the sizes its
# available entries hold, less two kinds of entry, each as it stands once
# the commands of the record are applied: an entry that holds no want, whose
# last want ended during the tick before, and that the closure of no root
# reaches; and an entry in force that holds a want and that an arrival to
# failed of the same record fails. An entry in force that holds no want at
# that step stays counted, though the record holds its arrival to failed:
# the arrival fails it only where a want of the first step names it, and
# that want is added only where the part that lists it is not rejected.
# The count is taken once, before the first group is tested: the room of an
# entry that the test itself brings to fail is free for no group of that
# record.
#
# An arrival to failed has no size and stands in no group. It is applied
# where a want names its asset when it is gone through, a want the core
# added at the first step included, and changes nothing otherwise.
#
# Reading taken, in "entry-due-to-fall": an entry due to fall that a closure
# reaches, and whose arrival to failed the record holds, is of neither kind
# the text leaves out, and two sentences keep it counted. It leaves the
# available entries at that fixed point whichever way the test falls, so
# the words "less what leaves the table's available entries at the same
# fixed point whatever the test gives" could be read to leave it out: that
# reading is a control.
# Reading taken, in "entry-under-the-want-of-a-parent": a want the core
# added is a want, so an entry that holds one alone holds a want.
#
# Every want of the family but the composition's is optional: the step
# names no failed asset, and no gate closes after tick 1.

# Scenario "first-load-fits-beside-the-entry". A budget of 9 000 bytes. B
# and D are in force, 6 000 bytes. One record releases the last want of D
# and holds an arrival to failed for D, the first load of P, whose part
# lists D, and the first load of N.

scenario count-without-want/first-load-fits-beside-the-entry
tick 0
entry B parameters unavailable
want contributor:base required
# Count 0. One root, B. Its group: 2 000, within, accepted.
tick 1

tick 3

event arrived D D.1
tick 5

want contributor:base required
entry D parameters available D.1 size 4000
want source:host optional
entry N parameters unavailable
want source:host optional
entry P parameters unavailable
want source:host optional
# The release is applied first: D is in force and holds no want. Its last
# want ended during this tick, so it is not due to fall; and it holds no
# want, so its arrival to failed takes nothing out of the count. Count
# 6 000. Roots B, N and P. The closure of P, read from the part of its
# arrival, is P and D; the arrival of D is to failed and stands in no
# group. The group of N: 11 000, above the budget, rejected. The group of
# P: 8 500, within, accepted.
# The wants of the accepted parts are added: the want of D under P,
# optional as the want of P is. The arrivals, in identifier order. D holds
# a want that the first step added: its arrival to failed is applied, and D
# fails. N, the root of a rejected group that a want names, becomes failed.
# P rises. At the recomputation P holds a want and a part in force that
# lists D: the want of D under P stands, on a failed entry.
# N is failed for the room of an entry that failed at the same fixed point:
# the count errs on the side of a rejection. The table ends at 4 500 bytes.
tick 6
record release D source:host
record arrival D failed unknown-asset
record arrival N N.1 size 5000
record arrival P P.1 size 2500
rejected N N.1
entry B parameters available B.1 size 2000
want contributor:base required
entry D parameters failed unknown-asset
want asset:P optional
entry N parameters failed over-budget
want source:host optional
entry P parameters available P.1 size 2500
want source:host optional
event failed D unknown-asset
event failed N over-budget
event arrived P P.1

# arrival changes nothing, and the table ends tick 6 with B, D and N in
# force: 11 000 bytes under a budget of 9 000.
