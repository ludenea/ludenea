# Oracles of the family "named-set": a named content set under a moved manifest.
# Written by hand from the design text as amended after the first stage,
# before any run of the same-harness stage, by a writer who has not read the
# build. Every state is derived again from the text, and none is patched.
# The table's order is the order of the asset identifiers: K1, K2, N, X2, X3, Y.
# Every asset of this family is of the first asset type, written "parameters",
# in each manifest and in each want, and no part of it is read as listing a
# dependency. An entry line states the type the entry holds, which its first
# want wrote.
# A tick 0 block states the table the creation gives, with an empty record and
# no event.
# No want of this family is made on an asset its world holds available: each
# names an unanswered asset, leaves the world at the end of its tick and is
# answered in the record of the next tick.
# Reading taken throughout: the events of a tick stand in the order in which
# its arrivals are applied, the order of the asset identifiers.
# Reading taken throughout: the step that runs the tick of a failed arrival
# names the required asset with its reason, and no later step names it again.

scenario named-set/moved-manifest

# The world created under the set. Every want that leaves it is resolved in
# the set's manifest, whatever has moved the instance's manifest since, and no
# revision, mount or unmount reaches its input record.
world under-set

tick 0
entry K1 parameters unavailable
want contributor:base required
entry K2 parameters unavailable
want contributor:base required

# The composition's wants are made before the first tick and gate it: their
# answers stand in the record of tick 1, and the tick runs with both applied.
tick 1
record arrival K1 K1.1
record arrival K2 K2.1
entry K1 parameters available K1.1
want contributor:base required
entry K2 parameters available K2.1
want contributor:base required
event arrived K1 K1.1
event arrived K2 K2.1

# Ticks 4 and 7 have no block: the revision and the mount post this world nothing.

# The first want of X2 makes its entry and writes its type. Tick 9 runs with
# X2 unanswered, and the world is gated from the boundary after it.
tick 9
record want X2 parameters source:host required
entry K1 parameters available K1.1
want contributor:base required
entry K2 parameters available K2.1
want contributor:base required
entry X2 parameters unavailable
want source:host required

# Answered at the set's hash: the former artifact is still in the store.
tick 10
record arrival X2 X2.1

want contributor:base required
entry K2 parameters available K2.1
want contributor:base required
entry X2 parameters available X2.1
want source:host required

entry K2 parameters available K2.1
want contributor:base required
entry X2 parameters available X2.1

want source:host required

# The mounted package overrides this entry on the instance: the set's hash answers.

want contributor:base required
entry K2 parameters available K2.1
want contributor:base required
entry X2 parameters available X2.1
want source:host required

want source:host required

# The set does not hold the asset, though the instance's manifest now does: a

want contributor:base required

want source:host required
entry Y parameters available Y.1
want source:host required

# The artifact the set names is gone from the store: a failed answer. The
# step that runs this tick names X3 alone: N failed at an earlier tick.

want contributor:base required
entry K2 parameters available K2.1
want contributor:base required

want source:host required
entry X3 parameters failed artifact-gone
want source:host required
entry Y parameters available Y.1
want source:host required
event failed X3 artifact-gone
names-failed X3 artifact-gone

# Tick 19 has no block: the unmount posts this world nothing.
# No want is added on a failed entry, so neither is loaded again.
# The table of tick 16 stands to tick 22.

# The world that names no set, on the same instance. The revision, the mount

scenario named-set/recording-replays-under-a-set

# One table for both worlds: the world that names no set, which makes the
# recording, and the world created under the set, which replays its input log.
# The set's hash is configuration: nothing in the table holds it.
# The sheet gives this scenario no last tick: nothing happens after tick 5.

tick 0
entry K1 parameters unavailable
want contributor:base required
entry K2 parameters unavailable
want contributor:base required

tick 1
record arrival K1 K1.1
record arrival K2 K2.1
entry K1 parameters available K1.1
want contributor:base required
entry K2 parameters available K2.1
want contributor:base required
event arrived K1 K1.1
event arrived K2 K2.1

# An optional want gates nothing: tick 4 runs with the asset unanswered. The
# want names an unanswered asset, so it leaves the world and is answered.
tick 4
record want X2 parameters source:host optional
entry K1 parameters available K1.1
want contributor:base required
entry K2 parameters available K2.1
want contributor:base required
entry X2 parameters unavailable
want source:host optional

tick 5
record arrival X2 X2.1
entry K1 parameters available K1.1
want contributor:base required
entry K2 parameters available K2.1
want contributor:base required
entry X2 parameters available X2.1
want source:host optional
event arrived X2 X2.1
