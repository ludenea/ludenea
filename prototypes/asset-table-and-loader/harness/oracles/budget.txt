# Oracles of the family "budget": an excess over a world's budget.
# Written by hand from the design text and from the definitions of the three
# candidates in the sheet, by a writer who has not read the build.
# Asset identifiers order as B, D, K, N, R, S, V, W, X.
# Record lines stand in the order applied: the commands first, in the order
# the scenario gives them, then the arrivals by asset identifier.
# An entry line with no want line under it is an entry that holds no want.
# A tick 0 block states the table the creation gives.
#
# Each case is stated three times, once per candidate, as the candidate's
# definition gives it. No candidate is chosen here. Under the candidate on
# the closure of one want every arrival to a hash carries its mark; under the
# two others no arrival does.
#
# The count of a world is the sum of the sizes of the contents its table
# holds available. The budget is 10 000 bytes but where a comment says
# otherwise. Sizes: B.1 9 000, D.1 6 000, K.1 5 000, K.2 11 000, N.1 2 000,
# R.1 2 000, S.1 1 000, S.2 2 000, V.1 1 000, W.1 1 000, X.1 9 000.
#
# Reading taken: the core adds the wants the parts of a batch list before any
# arrival is tested, and those wants stand whatever the test gives. A
# dependency keeps the want its parent's part gave it when the parent's
# arrival is rejected.
# The other reading: a want the core added from a part that is not put in
# force is taken back.
#
# Reading taken: a rejected first load is an answer, as any failure is. The
# gate opens on it, the step names a required asset, and the want does not
# leave the world again.

# The fourth candidate, "derived-closure": the unit the design text proposes,
# with the count and the rule on the wants the core adds that it proposes.
# Eight scenarios: the six cases above, and two cases that run under this
# candidate alone. Written by hand from the proposed text, by a writer who
# has not read the build. Nothing above this line is changed, and no state
# is taken from it: the oracles above stand under the other reading of the
# wants the core adds, and under a count that holds the entries that fall.
#
# The candidate writes no mark: an arrival is written as under
# "single-arrival". The sizes are a stand-in for the size the text proposes
# that an arrival names and that an entry holds: those of the sheet's table,
# with R.2 2 000, whose part lists D and X.
#
# At a fixed point, in this order: the commands of the record; the groups,
# derived and each decided before any want of the batch is added and before
# any arrival is applied; the wants that the parts of the accepted arrivals
# list, and those alone; the accepted arrivals, in identifier order; the
# wants the core added, recomputed from the parts in force; the falls.
#
# The closure of a root is read from the part in force and from the part of
# the arrival, from both where an asset has both. The wants that a rejected
# part lists are not added: an asset that a rejected part alone lists is
# named by no want, and its rejected arrival leaves no entry, no failure and
# no event. The result of the step names every rejected arrival all the
# same, as a "rejected" line.
#
# Reading taken: an arrival is applied or rejected at its place in the
# identifier order, so the event of a rejected root that becomes failed
# stands among the events of the accepted arrivals, by identifier.
# The other reading: the failures of the rejected roots stand before the
# events of the accepted arrivals, or after them.
#
# Reading taken: the groups are tested in the identifier order of their
# roots alone, a root under an optional want before a root under a required
# one where it stands first. The text leaves the other order open.
#
# Reading taken: the batch of a revision holds an arrival for each asset
# that changed and for each asset that a changed part newly lists, and none
# for a dependency that did not change and that the table holds available.
# The other reading adds such an arrival to the record; it changes nothing.
#
# Reading taken: a want made on an entry the table holds available is
# answered already, and no arrival follows it.
# The other reading: an arrival at the hash the entry holds follows it, at
# the next tick; it changes nothing.
